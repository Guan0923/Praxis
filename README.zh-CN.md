# Praxis

**让想法落地。在你的电脑上，按你的方式。**

Praxis 是运行在本机、通过浏览器使用的个人 AI 工作空间。交给它一个任务，带上相关文件，一起把事情做完：读懂项目、修改代码、执行命令，或查找网页资料。计划、工具结果和权限确认都在对话中展开，让你看得到过程，也能决定下一步。

## 带来一个任务，不只是一个问题

一个有用的助手，应该帮你把工作往前推进。你可以从自己的项目出发，试试这些任务：

| 从这里开始 | 一起做到这里 |
| --- | --- |
| “解释这个项目怎么启动，帮我找出关键文件。” | 对照真实代码，建立对项目的理解。 |
| “找出这个报错的原因，先说修改方案，不要直接改。” | 先讨论计划，再检查具体实现。 |
| “读一下这些日志，把反复出现的问题整理成简短报告。” | 将结果写进工作区，而不只留下一段聊天回复。 |
| “查一下这个功能的文档，比较几种实现办法。” | 把网页资料带回当前任务，一起判断怎么做。 |

这些是任务示例，不是性能测试结果。实际完成情况取决于所选模型、可用工具和你授予的权限。

## 从想清楚，到做出来

### 先讨论，再行动

用 **Plan 模式**探索问题、讨论方案；准备好后，切换到 **Agent 模式**执行。相关文件、命令和结果与对话放在一起，方便你回看发生了什么，再决定下一步。

### 项目有各自的位置，对话有自己的上下文

分别管理项目和对话，在消息中引用文件，在侧边面板查看工作区内容。继续之前的讨论，或探索另一个方向，不必把所有事情塞进同一条长对话。

### 按自己的工作方式扩展

在设置中连接你选择的模型服务。用 **Skills**加入可重复使用的指令和工作流程，或通过 **MCP 服务**接入外部工具。项目提供的指令和外部工具仍需经过相应的信任与权限检查。

### 本地运行，清楚授权

不需要注册 Praxis 账户，也不依赖云同步服务。应用数据保存在你的电脑上。工具操作受工作区范围和审批规则约束；严格沙箱不可用时，不会偷偷改用不受限制的普通进程执行。

## 快速开始

以下开发流程面向 **Windows**。命令隔离依赖 Windows 沙箱服务，不代表其他系统具备相同的沙箱支持。

需要准备 **Python 3.11+**、**Node.js 20+**、**uv**。如果使用项目约定的 Conda 环境，请先执行 `conda activate dev`。你还需要一个有权使用的模型服务。

在仓库根目录执行：

```powershell
uv sync --locked
cd frontend
npm ci
cd ..
uv run python -m backend.api
```

另开一个终端，从仓库根目录执行：

```powershell
cd frontend
npm run dev
```

打开 **<http://127.0.0.1:5173>**，然后：

1. 进入**设置**，填写模型服务、接口地址和模型名称；需要密钥时填写 API Key。
2. 检查**沙箱**设置。安装 Windows 沙箱需要管理员授权；就绪前，需要沙箱的命令会被阻止执行。
3. 新建对话或打开项目，引用相关文件，再描述任务。希望先确认方案时，从 Plan 模式开始。


想只运行一个应用服务，可以先在 `frontend/` 中执行 `npm run build`，再启动后端，通过 <http://127.0.0.1:8000> 使用构建好的页面。

## 数据与权限

- **保存在本机：**配置、项目、聊天历史和工作区文件使用 `~/.praxis`。模型服务的 API Key 加密后保存，不写进 TOML 配置文件。
- **本地不等于离线：**使用在线模型时，相关请求内容会发送给所选服务。网页工具和外部 MCP 服务也可能向外发送数据，请按任务选择服务与权限。
- **没有应用登录：**Praxis 面向本机单用户使用，不是共享的公网服务。模型服务和外部工具可能需要各自的凭据。
- **作为新安装使用：**这个版本不导入旧安装的数据或密钥。现有用户需要重新配置 Praxis，具体说明见[安装说明](docs/development.md#praxis-installation)。
