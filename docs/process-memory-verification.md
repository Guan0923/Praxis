# 删除外部消息服务，改用进程内队列与缓存

验证日期：2026-09-11。

## 实施范围

- 工作分支：`codex/redis-sandbox-recovery`，继续使用原 worktree。
- 保留此前沙箱连续不健康 10 秒才修复、修复后观察 10 秒的改动。
- 没有提交、合并、推送或重启现有服务；没有操作现存容器、数据卷和业务数据。
- 未实施对话数量淘汰、默认 5 个 Turn、历史分页或终端前后缀摘要。

## 删除与替换

- 删除原消息服务实现、Lua、消费者组、连接配置、健康检查、Compose 服务以及 Python 依赖；锁文件同时移除不再需要的 async-timeout。
- MemoryMessageQueue 是唯一生产实现，承载 Turn 启动、运行中消息、Agent mailbox 和报告。启动 worker 使用条件等待，关闭时唤醒并清空消息。
- TurnMailbox、AgentMailbox 保留安全边界消费与 SQLite 写入成功后确认的顺序。失败可在当前进程内重试；不跨后端重启重投。
- 运行事件、Todo 和终端输出改为线程安全内存对象，保留事件和终端输出数量限制，不设置数据过期时间。
- SSE 使用进程标识与不透明游标，订阅先读取快照；事件缓存缺口触发重新发送快照。去重记录随实际保留的事件释放，多个对话互不覆盖。
- 删除 SQLite 的事件补发记录写入、读取、确认和后台补发循环；保留正式消息、Trace、增量落盘与序号。不扫描或迁移旧补发记录。
- 正常关闭取消工作、保存中断状态并清理资源；异常退出留下的运行状态在访问会话时标记为中断，不自动执行旧任务。
- 就绪接口仅检查本地数据库；其余业务 API 和前端消息格式保持不变。

## 实际验证

- 完整后端测试：1283 passed、49 skipped、1 failed，耗时 342.11 秒。结果位于 `.test-tmp/process-memory-final.xml`。
- 随后的最终内存、Todo、缓存边界专项测试：34 passed。结果位于 `.test-tmp/process-memory-focused.xml`。
- 唯一完整测试失败为既有测试 `test_legacy_schema_is_rejected_without_mutating_or_deleting_database`：测试仍要求 v16，实际代码要求 v17。本轮未修改数据库版本或放宽该测试，不能视为全套通过。
- 跳过项涉及显式 Docker/下载验收、缺失的隔离 MCP v1 测试环境以及 Windows 不支持的 POSIX/符号链接测试；没有将跳过计为通过。
- Ruff、格式检查、锁文件检查通过；前端类型检查、442 项 Vitest 和构建通过。构建仍有原有的大文件提示，测试仍有原有的 jsdom/组件弃用提示。
- 完整测试实际运行了 4 个浏览器场景：聊天控制、连续富文本、Todo、SQLite 写入失败；检查了桌面和窄屏截图。
- 真实 Windows PTY 执行命令并读取输出；真实子进程使用独立目录以退出码 17 强制结束，验证消息丢弃和 SQLite 历史保留。
- 测试使用临时数据库、独立监听端口和本地模型 HTTP 服务，不调用付费模型 API。测试不再通过全局 fixture 替换生产队列，直接使用默认实现。

原有 outbox 大小比较已随被删除的接口移除；原测试中的本地 HTTP 小分片延迟比较保留。新测试直接验证正式增量仍持久化且不再写入补发记录。
